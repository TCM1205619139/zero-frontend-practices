# Vue 文件书写规则

## 组件的书写规则：

1. 尽量利用 computed 去动态渲染，减少 template 中的逻辑判断，保持模板的简洁和可读性。在命名 computed 属性时，使用有意义的名称，能够清晰地表达其作用和返回值，避免使用过于抽象或模糊的名称。例如，针对渲染使用的就使用 renderXXXX，针对计算属性的就使用 computeXXXX，针对状态的就使用 stateXXXX 等等，这样能够更好地组织和管理 computed 属性，提高代码的可维护性和可读性。
2. 一般来说，同一个组件会写两遍，一个 mobile.vue，一个 pc.vue，分别适配移动端和 PC 端，然后将变量和操作提取到一个hook中，保证。
3. 需要区分容器组件和内容组件，内容组件宽度为100%，继承容器组件的宽度，容器组件负责布局和样式，内容组件负责展示数据和交互，内容组件内部最外层dom尽量不要给 padding，margin等。
4. 编写 vue 组件时，如果需要用到 store，尽可能使用 storeToRefs 来解构 store 中的响应式数据，避免直接使用 store 进行访问，这样能够更好地利用 Vue 的响应式系统，提高组件的性能和可维护性。
5. 进行重构，迁移和开发时，按照以下工作流进行（每次执行前进行询问）：
   - 开启 subagent 模式
   - subagent 构成：一个主agent + 多个 subagent，主 agent 负责整体的工作流程和协调，subagent 负责具体的任务执行。
   - subagent分工：一个 subagent 负责 code 开发，一个 subagent 负责 code review 和测试，确保代码质量和功能正确。一个 subagent 负责验证代码可读性和可维护性（结合项目上下文）。
   - 主 agent 负责监督整个流程，确保每个 subagent 都按照预定的工作流程执行，并在必要时进行协调和调整，以确保项目的顺利进行。
   - 每个 subagent 在完成自己的任务后，需要向主 agent 汇报工作进展和结果，主 agent 根据汇报情况进行下一步的工作安排和决策，确保项目能够按时完成并达到预期的质量标准。

## 多语言：

1. 所有的文案都需要进行国际化处理，使用 i18n 插件进行翻译和管理，确保应用能够支持多语言环境。
2. 不同的情况使用不同的翻译实现方式：
   - 纯文本：直接使用 $t('key') 进行翻译。
   - 带有变量的文本：使用 $t('key', { variable }) 进行翻译，确保变量能够正确替换。
   - HTML 内容：i18n-t keypath="key" tag="span", template #slot 进行翻译，确保 HTML 标签能够正确解析。
